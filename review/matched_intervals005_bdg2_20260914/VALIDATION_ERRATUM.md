# Native CQR validation and method-description erratum

The real pilot exited **0**, completing all 30 method cells with the evaluated native factories. Its first independent validator exited **1** at the first native CQR reconstruction: a constant lower-bound discrepancy of 0.56145574 kWh. No learned or calibrator fit occurred during validation.

The validator and original method-description string incorrectly assumed a symmetric max-score correction. Installed MAPIE 1.4.1 `ConformalizedQuantileRegressor.predict_interval` defaults to `symmetric_correction=False`. The evaluated generator called that default. Thus its actual native intervals used separate lower-tail scores `raw_lower-y` and upper-tail scores `y-raw_upper`, each with `numpy.quantile(score, (1-(1-level)/2)*(1+1/n), method='higher')`. The method-preserving online CQR replay contract continues to use `max(raw_lower-y,y-raw_upper)` and its declared ranks. No online CQR experiment was added.

[The no-fit diagnosis](cqr_native_diagnosis.csv) reconstructs all six native CQR cells **exactly**, maximum bound difference 0. The saved estimators, calibration scores, issued intervals, point forecasts, memberships, scientific settings, output metrics, original protocol and original source archive were not changed. The correction changes the independent reconstruction and the description of the already evaluated native default; it does not choose a correction based on performance. The completed values are valid for that native asymmetric CQR construction, not a symmetric CQR variant.
