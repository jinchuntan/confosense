# Native EnbPI points: exact float32 CSV roundtrip

The third validator passed native CQR reconstruction and the corrected float64 EnbPI OOB-score reconstruction. It then exited **1** because it added interval offsets to the cached point column after reading float32-formatted decimals as float64. Near-zero bounds exposed the resulting absolute discrepancy under the unchanged tolerance.

XGBoost's native predictions are float32. Pandas writes their short decimal representations to CSV. Reading those decimals as float64 is numerically close, but is not the exact original float32 value represented in float64. Restoring the original float32 dtype recovers **all points exactly**. Adding independently reconstructed native offsets to predictions reloaded directly from the saved owner passes **all six EnbPI native interval cells**; maximum bound discrepancy is **2.2737367544323206e-13 kWh**. See [the full diagnosis](enbpi_bounds_diagnosis.csv).

No issued bound, cached point, saved owner, calibration score, membership, metric, parameter, or tolerance was changed. Point and interval metrics continue to describe the exact saved streams. The corrected validator explicitly verifies the exact float32 point roundtrip, reconstructs native bounds from actual reloaded predictions, and retains all previous independent checks. This is a reconstruction/serialization-precision correction, not a new scientific run.
