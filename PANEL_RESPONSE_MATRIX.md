## Short explanation for the panel

A point forecast gives one expected sensor reading. Conformal prediction uses prediction errors or conformity scores from separate calibration data to construct a range around a forecast. The range communicates uncertainty: a reading outside it can prompt attention, and repeated violations can trigger an alert. A nominal 95% interval expresses a target for long-run coverage under the method's assumptions; it is not a 95% probability that a detected event is a real fault. Temporal dependence and changing building conditions require empirical checking. This explanation follows the [conformal prediction tutorial by Angelopoulos and Bates](https://arxiv.org/abs/2107.07511).

Illustrative only: a temperature forecast of 24°C with a 22–26°C interval gives the operator more information than 24°C alone. Three violations among the last five observations could trigger a persistence rule. With ten-minute sampling, five observations represent a 50-minute monitoring window; the actual experiment uses its declared physical-time candidates, not this illustrative rule by default. Extremely wide intervals can cover almost everything while being poor monitors. Coverage, width, missed synthetic events and alert workload must therefore be read together.

In this project, the defensible motivation is **uncertainty-aware monitoring under imperfect data**, with observed trade-offs and limitations. Improved energy use, measured SDG impact and real fault precision were not established.

### What can be done from saved data, without fitting

The historical `combined/point_metrics.csv` can be summarized by matching dataset and horizon, explicitly as pre-repair diagnostics. Preliminary `outputs/predictions/point_predictions_h*.csv` and laptop-verification PLEIA prediction rows contain both models and allow common-row error comparisons. These are different, historical runs; first audit nonmissing common support and label their provenance.

Older full-study per-observation prediction directories are absent locally. The corrected core has no point predictions or interval bounds. Consequently, corrected LSTM–XGBoost coverage/width/Winkler and paired error CIs **cannot** be recovered by postprocessing the available core CSVs. Calibration residuals cannot be inferred from aggregate point errors. Do not use test residuals to manufacture missing calibration data.

### Smallest new-fitting comparison, only after validation and approval

Use the existing two model families and persistence context on the already declared datasets/splits; start with the already selected primary horizon per task, explicitly identifying this as a bounded comparison rather than completion of the whole multi-horizon grid. Use the existing methodological nominal levels, **90% and 95%**, matched across models. A broader horizon grid is required only if the final claims retain that scope.

Use a common, explicitly declared calibration construction around **each model's own predictions**. A residual-based construction already represented in this repository is a candidate; confirm its finite-sample quantile rule and temporal assumptions before adopting it for this comparison. This would be a reviewed protocol clarification/change, not permission to relabel HistGBR CQR as an LSTM method. If the dissertation specifically requires quantile-LSTM CQR, that requires additional quantile-model implementation and is not the minimal task.

Acceptance criteria for an authorised comparison:

- Same outer test timestamps/groups, horizons, information available at prediction origin, calibration scope, nominal levels and evaluation masks. Tune using permitted inner data only; fit scaling on permitted training data only.
- Persist per-row truth, prediction, lower/upper bounds, model identity, dataset/fold/seed/horizon/level, and calibration/provenance hashes. Explicitly report missing/inapplicable cells and execution errors.
- Compute coverage, MPIW, Winkler, MAE and RMSE on common support. Pair model differences within the same unit; aggregate algorithmic seeds before run/building/period inference. Retain NA CIs where independent support is insufficient rather than creating pseudo-replication.
- Time tuning, final fitting and inference separately under recorded hardware/thread/batch conditions; account for asynchronous device execution if relevant. Measure process peak memory and accelerator memory where actually used. Historical smoke times are not a baseline for this comparison.
- Assess both interval usefulness and costs. Wide intervals or absent coverage cannot be offset by a favourable point-error number. A conclusion that the extra LSTM cost provides no demonstrated benefit is acceptable.
