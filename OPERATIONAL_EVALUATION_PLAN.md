## 1. Nested fitting, calibration and operational selection

For every dataset/primary-horizon/outer-fold unit:

1. Reuse `make_outer_folds` and repaired strict target-time/group boundary checks. Outer fold IDs remain 0, 1, 2 in existing order, with actual endpoints saved. Do not reinterpret fold 0 as the earliest chronological fold.
2. Reserve the last 25% of permitted pre-test development data as **final calibration** using `split_integrity.refit_split`. No final-calibration or outer-test values may select a method, level, rule, epoch, threshold, update window or event scale.
3. Divide the remaining fitting pool into four chronological equal blocks B0–B3 with `ordered_blocks`, purging straddling targets at every cut. RICO blocks consist of whole runs; BDG2 uses common times across buildings. Never substitute row-count cuts through groups.
4. Operational inner fold 0: fit B0, calibrate B1, select B2. Operational inner fold 1: fit B0+B1, calibrate B2, select B3. Each boundary requires `max(previous target_time) < min(next origin_time)`. Blocks may play different roles in later expanding folds, but no fold uses its own future selection outcomes in fitting/calibration. Record the overlap structure; the two scores are not independent replicates.
5. Any point hyperparameter or early-stopping search occurs inside that fold's fit block, using its own purged development split. Initial implementation keeps the existing interval estimators' recorded fixed fitting parameters, avoiding an unbudgeted new point-model search. Store actual class, parameters, fallback and seed. A future change to fitting budgets needs its own version.
6. Each candidate is evaluated on **both** selection blocks, with the same eligibility masks, events, clean counterfactual and rules as every comparator. Missing/inapplicable folds cannot be dropped to improve an average. After selection, refit the selected predictor on all B0–B3, calibrate once on reserved final calibration and freeze the operational configuration before outer evaluation.

Selection is per model seed, never selection of a best seed. Use **all five catalogue seeds for each model seed**, averaging catalogue outcomes rather than treating them as extra independent assets. This explicitly crosses the two declared five-seed ledgers instead of the current one-to-one zip, which confounds model randomisation with event placement. It increases event replays, not the number of final fitted models; a resource smoke must measure that additional cost before a full launch. The 60 primary core fitting units remain four tasks × three outer folds × five model seeds.

## 2. Event schedules, exposure, family weighting and observation model

### Common schedules and denominators

Create catalogues once for each dataset, fold role and catalogue seed, independently of candidate scores and model seed. Share the schedule across all methods, operating levels, policies and ablations. Separate inner-0, inner-1 and outer namespaces in a deterministic SHA-256-derived seed; retain the master seed and resulting integer. Store each event's group, onset/end timestamps, type, severity code, sign, duration, attempted/rejected status and placement reason.

Exposure is the union of valid monitored sampling intervals within each asset, in days, after common feature/forecast warm-up; duplicated rows, overlapping windows and repeated catalogues do not create more exposure. A missing acquisition interval is not silently treated as observed time. Stop/reset rolling state at actual time gaps and group boundaries. A target-missing synthetic fault does not remove its scheduled exposure: retain the pre-injection mask, availability flag and clean truth.

Per catalogue, the requested event count is `floor(0.5 * total eligible asset-days + 0.5)`. **Remove the undeclared eight-event minimum from scientific runs.** If the declared incidence yields no events or insufficient support, report it; do not manufacture incidence to make a configuration feasible. Allocate events across hostable groups in proportion to their eligible exposure by largest remainder, ties by stable group ID. Allocate the 21 family/severity strata globally, with counts differing by at most one; rotate the deterministic starting stratum across catalogue seeds. Do not restart the stratum cycle independently in each short group.

Retain requested exposure/count, hostable exposure, placed/rejected counts, requested and realised incidence, per-group allocations and each stratum's support. Unhostable requested events remain explicit rejections. Make at most 1,000 placement attempts per event, then mark `unplaceable`; no silent retry in another dataset. Event/tolerance windows must not overlap within a catalogue. Existing common forecast eligibility supplies feature/sequence warm-up; require one observable predecessor for a fault onset. Use a between-event guard of `max(longest applicable alert window, detection tolerance)` to prevent residual alert episodes being credited to a second event. At a group's end require only the complete detection-tolerance follow-up, since alert state terminates there. A short RICO run may host one event; it is not required to provide six hours of extra end padding. Initial preselection calibration history may warm the stream but cannot be scored as selection exposure.

### Exact family definitions (amendment)

Keep the seven family identifiers and severity codes 0.5/1/2. Specify a common fault envelope of **max(60 minutes, four sampling intervals)**, converted upward to an integer number of samples. The four-sample floor is a declared amendment: one hourly sample cannot distinguish a ramp from a step. At least one complete envelope plus its guard must fit inside the group. Signs alternate deterministically within strata and catalogue seeds. The original four-type implementation makes bias and level shift identical, and ignores stuck severity; it must not be reused as a seven-family implementation.

| Family | Observable sensor corruption inside the envelope | Severity mapping |
|---|---|---|
| `random_missing` | Independently mark scheduled readings unavailable using the catalogue RNG; keep the realised mask. | Missing probability `0.2 * severity`: 0.10, 0.20, 0.40. |
| `block_missing` | One contiguous centred unavailable sub-block; other readings remain observable. | Fraction 0.25, 0.50, 1.00 of envelope, rounded up. |
| `stuck` | Hold the last available reading before the fault during a contiguous sub-block; do not consult future clean values. | Duration fractions 0.25, 0.50, 1.00, rounded up. |
| `dropout` | Sensor reports numerical zero (distinct from an unavailable reading). | Duration fractions 0.25, 0.50, 1.00, rounded up. |
| `bias` | Gradual additive bias: linear rise over first quarter, plateau over middle half, linear fall over final quarter; envelope endpoints defined in the catalogue. | Plateau magnitude `sign * severity * train_robust_sigma`. This specifies a gradual bias distinct from an abrupt level shift. |
| `level_shift` | Abrupt additive rectangular offset throughout the envelope, followed by restoration of the sensor. | `sign * severity * train_robust_sigma`. This is a temporary sensor-level shift, not proof of a physical building fault. |
| `drift` | Additive linear ramp from zero to signed magnitude; restore at envelope end. | End magnitude `sign * severity * train_robust_sigma`. |

For n envelope samples indexed j=0,...,n−1, use u=j/(n−1), bias multiplier `min(4*u, 1, 4*(1-u))`, and drift multiplier u. A duration-fraction sub-block has length `ceil(n*fraction)` and begins at `floor((n-length)/2)`; stuck and dropout use that same centred placement. Random-missing uses a separate event-keyed RNG substream so candidate order cannot change its mask. Zero severity bypasses corruption before rounding duration or drawing masks. These formulas fix discretization, including the four-sample BDG2 floor.

The SD interpretation applies only to additive families. Report missingness probability/duration explicitly for the other four; never label their severity as an observed SD displacement. At coarse sampling, record any identical realised severity masks as aliases, not independent evidence. Preserve the zero-severity identity control for every family. The extension's already declared five-type/severity/window design remains a separately versioned analysis; do not silently replace it with this core catalogue.

Use training-only per-group MAD-to-sigma, with recorded pooled-training fallback for new/degenerate groups; no calibration/test scale estimates. Unavailable readings use the last *observable* value within that group for model inputs, plus a retained availability mask. A gap with no available predecessor is unforecastable, explicitly accounted for on the common eligibility mask. Missingness itself counts as an availability violation in the operational alert stream, in addition to numerical interval violations; save the two causes separately. Clean truth is used only for evaluation, never to update a corrupted sensor's model/residual stream. This is a proposed monitoring rule, not evidence that the legacy interval-only code detected missing data.

### Event recall and weights

For each catalogue, calculate detection proportion in each (family, severity) stratum. Within a fold, pool event counts/detections across the five catalogues **within each stratum**, then average the 21 stratum recalls equally: equal seven-family weight and equal three-severity weight. This pools simulation schedules for the point estimate but does not multiply independent time/group support for inference. A stratum absent across all five catalogues makes the full macro estimate unavailable; an observed-strata-only mean may be reported as a diagnostic with its denominator, never as the full macro recall. Report per-family/severity and pooled micro recall alongside it. Report per-group recall separately; equal-stratum and equal-group macro averages answer different questions and must not share an unlabeled `macro` column.

## 3. Physical alert rules, episodes and matching

The operational candidate is one immediate **1-of-1 sample** rule plus the six physical pairs **(5 min,2), (15 min,3), (30 min,3), (60 min,4), (180 min,3), (360 min,4)**. Relabel the old `1min-1of1` as `single_sample`: the engine already treats it as immediate at every frequency, whereas a literal one-minute window is inapplicable to 10-minute/hourly data. For each other pair use `m=floor(window_minutes/frequency_minutes)`, retain k, and mark inapplicable when m<1 or k>m. Names must show actual k/m and physical duration; do not preserve misleading suffixes such as “3of5” when the conversion is 3-of-15.

Retain no latching, zero minimum duration, zero clear duration and zero cooldown. Aggregate only within a contiguous asset segment; a new segment starts with no rolling history and no cross-gap state. Permit the existing partial initial window (`min_periods=1`) after the declared warm-up. Build episodes before event matching. Score time in alert from the union of flagged monitored intervals, not episode count × window length.

Preserve configured detection tolerances, expressed physically: **PLEIA temperature/energy 60 minutes, RICO 10 minutes, BDG2 180 minutes** (existing 6, 10 and 3 steps). Sort events by `(group,onset,event_id)` and episodes by `(group,onset,episode_id)`. Greedily assign the earliest unused episode onset in `[event onset, event end + tolerance]`; each episode/event may be matched once. A pre-onset active episode earns no detection credit, including one crossing the event onset. Nonoverlap of guarded event windows makes matching deterministic. Clip follow-up only at a documented segment boundary; events lacking full follow-up are censored/ineligible for the main complete-window recall, with counts preserved.

## 4. Workload, delay, precision and utility

**Primary workload** is all episode onsets on the paired, unmodified counterfactual stream divided by its monitored asset-days. Replay its own calibration state and observations. Do not use only unmatched episodes on the injected stream as the clean-workload denominator/numerator. Report corrupted-stream unmatched/duplicate/cascade episodes separately. For BDG2, retain both sum(episodes)/sum(building-days), equal-building mean rate, and sum(portfolio episodes)/calendar-days with at least one building monitored; the portfolio quantity is not per-asset workload and has no 1.0/asset-day constraint.

Detection delay is episode onset minus event onset in minutes. Report median and q90 **among detected events**, with detected/eligible counts. Also report the undetected fraction and restricted mean time to detection over the common event-envelope-plus-tolerance horizon, treating misses as right-censored at that horizon. Do not fill missed delays with zero or silently omit them from an all-event delay claim. Variable follow-up receives a censoring indicator and remaining follow-up duration.

Keep beta=1 and the declared synthetic F-beta utility, but define its precision component: for a stratum s, use `P_s=TP_s/(TP_s + unmatched_episode_count/21)` on the injected stream, allocating every unmatched episode equally across the 21 strata, including duplicate alarms inside event windows. `R_s=TP_s/N_s`; `F_s=2*P_s*R_s/(P_s+R_s)`; zero detections with events gives F_s=0, and absent event support is unavailable. Macro F1 is the equal mean of F_s. This is an explicit synthetic utility convention, not a real-fault precision estimator. Report overall matched-events/all-episodes precision separately at realised catalogue incidence. The clean-workload feasibility gate remains independent of that convention.

Within a fold, calculate recall, precision and F1 from the catalogue bank's pooled stratum counts and pooled unmatched count; average catalogue-specific clean-workload rates equally. Pool detected-event delays across that bank for the fold's median. The final selection score is **0.5 × inner-0 macro F1 + 0.5 × inner-1 macro F1**. Delay tie score is the equal mean of the two detected-event median delays. Neither more rows nor more events in one fold gives it more selection weight. Sensitivity at **0.25 and 1.0 events/asset-day** is a later secondary replay of frozen pipelines, with new fixed catalogue namespaces; it never selects a different pipeline and is not part of the next smoke.

## 5. Feasibility bounds, support and abstention

Calculate group/time-aware 95% percentile intervals from **2,000** paired resamples, seed 20240601. Retain all candidates, catalogue seeds and relevant seed contributions in the same sampled cluster/time block. For PLEIA, resample moving blocks of chronological **time contributions**, length `max(round(sqrt(n_monitored_steps)), longest alert window + event envelope + tolerance in steps)`. Carry full context for matching at block edges; assign an event by its onset and an episode by its onset so neither is split or double-counted. Do not bootstrap only the list of event rows or concatenate blocks and rerun episode merging across artificial joins. For RICO resample whole runs; for BDG2 whole buildings. Save the resampling indices and effective number of original units.

Bounds use the 2.5th percentile for recall and 97.5th for workload. Require, in **each** inner fold: all 21 strata observed; at least five distinct placed onsets per stratum across the catalogue bank; at least five original resampling groups or five nonoverlapping blocks of the specified length; finite estimates; and at least 1,900 valid replicates. Missing strata in a replicate make that replicate unavailable, not zero or dropped from its macro denominator. Record actual valid-replicate count. Degenerate/nonidentifiable bounds (including bootstrap all-zero workload or all-perfect recall with no variation) are `insufficient_bound_support`; **do not treat a zero-width interval as certainty or fall back to a point estimate**. Small/short tasks may legitimately lack operational feasibility evidence at the declared incidence.

A candidate is feasible only if **both folds** have valid bounds with recall lower bound ≥0.60 and clean-workload upper bound ≤1.0 episode/asset-day. Report equal-fold aggregate estimates as well. Requiring both folds, rather than letting an easy fold mask a poor one, is a declared conservative clarification. These are approximate inner screening bounds, not simultaneous guarantees over the searched grid or a population deployment certificate. Independent outer scoring and explicit post-selection limitations remain necessary.

Sort feasible candidates by: descending equal-fold macro F1; ascending equal-fold detected-event median delay; ascending equal-fold clean workload; ascending immutable candidate ID. Treat undefined delay as +infinity. Use exact computed values; no score-dependent tolerance or performance-driven tie change. Freeze candidate IDs from method/level/policy settings/physical-rule order before execution.

If none is feasible, return `no_feasible_configuration` with every rejection/support reason and no operational pipeline. Do not drop that unit or promote a best-effort configuration. For comparison completeness, a **predeclared fixed diagnostic CQR 95%, static, single-sample pipeline** may still be evaluated, explicitly `operational_feasible=false`; this replaces test/inner-score-selected “best effort” for abstaining units. Diagnostic results must remain outside feasible-operation headline claims. Software errors, unsupported design, and scientifically infeasible configurations are separate statuses.

## 6. Recalibration and the actual alert stage

Keep the declared static/periodic/rolling strategies. Use the existing dataset grids, not the core's hardcoded 48/250/30: PLEIA update-every {24,48,144} steps and rolling windows {250,500,1000}; RICO {15,30,60} and {200,500}; BDG2 {12,24,48} and {200,500}; declared minimum samples **50**. Record their physical durations. Select settings only through the two operational folds. Initial calibration needs 400 observations and a supported order-statistic rank at the requested level; online updates additionally require 50 finite observed scores and finite rank support. Otherwise retain the last valid calibration, record why and its age, rather than silently broadening/retuning the grid.

Periodic uses all eligible historical calibration and matured online scores; rolling uses the latest `window` such scores, ordered by target observation time, including the calibration tail. Both recompute at group-local origin indices 0, every, 2×every, and retain the last correction between boundaries. Gaps reset the segment clock and online state, retaining only the explicitly permitted historical calibration pool. Static never updates. Missing readings add availability alarms but no numerical residual. Reject nonfinite scores; record pool sizes, skipped updates and correction age.

For CQR at nominal level L, choose the ordered score at one-based rank `ceil((n+1)*L)`. For signed residuals, alpha=1−L, choose lower rank `floor((n+1)*alpha/2)` and upper rank `ceil((n+1)*(1-alpha/2))`. A rank outside 1,...,n is unsupported, never clipped to a convenient empirical percentile. This replaces the operational signed-residual helper's interpolated quantiles with explicit finite-sample ranks as an amendment; it does not retroactively modify historical outputs or assert exchangeability of the streams. A small rolling pool may retain its last valid correction at high levels; report that actual behavior rather than calling it a successful update.

Preserve method semantics. Static CQR must use its fitted lower/upper quantile curves plus its CQR score correction, not signed point-residual quantiles. Periodic/rolling CQR update **CQR nonconformity scores** `max(q_lower-y_observed, y_observed-q_upper)` for stored forecasts. Signed-residual methods update their own signed residuals; uncalibrated quantile bounds remain a diagnostic with no conformal correction. The current `_recalibrated_stream('static', ...)` can replace method-specific bounds with a common residual construction in inner selection; that is a confirmed operational integration gap, outside the pilot's fixed split-conformal path.

Represent native updated EnbPI as a canonical online-residual policy, not a method that is adapted once internally and again by a second wrapper. Preserve its existing every-origin expanding update as the single explicitly named `native_updated` policy (every=1); apply the same support rules above. Other periodic/rolling candidates use the declared dataset grids on the same fitted base. Collapse duplicate combinations of the historical static/updated method labels and identical wrapper settings to one candidate. Uncalibrated quantiles have only their unmodified policy. Save the base estimator and exact conformity-score/update construction. Method labels must reflect which bounds actually execute. The project's recentred/updated adaptations do not automatically inherit every guarantee of published EnbPI.

At forecast origin t: ingest only observations with timestamp ≤t; release matured residuals whose stored forecast target time ≤t; apply scheduled policy update; build inputs through t; predict target t+h and save raw bounds/point/conformity inputs. At that target's observation time, compare the available reading with the bounds that were actually issued and then update the group's alert state. Record alarm onset in **observation/target time**, not h steps earlier at the forecast origin. Each clean/corrupted replay has separate residual state. Never feed the current target's clean truth to the corrupted path, and never update a forecast using its not-yet-observed outcome. Group/run boundaries reset state; a new RICO run may use only the fixed historical calibration pool, with that assumption recorded.

Hash the exact lower/upper arrays and availability flags consumed by `alert_on_stream`; assert they equal the selected policy's emitted stream. In closed-loop mode corruptions enter future lags, sequences and observable residuals causally. Fixed-interval mode uses clean-issued forecasts solely as a clearly labeled diagnostic. Do not claim a closed-loop alarm result from merely injecting the final comparison array after forecasts/recalibration have already run on clean readings.
