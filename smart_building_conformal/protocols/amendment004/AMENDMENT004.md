## Explicit implementation clarifications

1. The plan's phrases “allocate across hostable groups” and “unhostable requested events remain explicit rejections” conflict. Requests are allocated across **all observed asset exposure** by largest remainder; unhostable assets retain rejected requests. Nothing is redistributed to manufacture support. The no-fit preflight used this rule before any new fit.
2. Event onset/end refer to the scheduled envelope's first/last reading. Bias/drift may begin with a zero offset; duration faults may affect only its centred sub-block. A positive schedule is null only if its entire envelope changes neither values nor availability. Stuck holds the last observable reading before its actual centred held sub-block. One observable predecessor is required; guards leave the declared number of complete clean sampling slots between envelopes, and only detection follow-up is required at a segment end.
3. Mask aliases compare *relative envelope masks*. They are not claims that distinct scheduled times are independent evidence. Numerical families retain their distinct amplitude/shape definitions. Source-provided missingness flags cause acquisition segmentation; imputed source values without such flags remain a provenance limitation.
4. Calibration scores are pooled for initial method calibration. Online histories use same-group calibration where available, otherwise the explicitly recorded historical pooled fallback, including for a new RICO run. New segments discard online history and reset the schedule clock. Fixed predictors may batch causally constructed feature rows; all outcome-dependent updates still follow observation/origin order. Numerical and availability episode channels are recomputed from the actual issued stream.
5. If any PLEIA acquisition segment is shorter than its declared moving-block length, its CI is marked unsupported rather than dropping that exposure or silently changing block length. Counts alone never certify identifiable bounds.
6. When a selected/fixed reference has an immediate rule, the controlled temporal contrast uses the first applicable temporal rule in declared order. It is labelled a controlled diagnostic, not an independently proven feasible component. The secondary inverse selector requires supported recall/workload bounds but removes the primary workload ceiling, minimises equal-fold point workload, then breaks ties by utility, delay and ID. Its separate label prevents conflation with primary feasibility.
7. Literal asset identifiers such as PLEIA's string `None` are read with explicit string converters in the new checkpoint runner. The optional checkpoint schema leaves historical reader defaults unchanged. Without it pandas would turn that identifier into a missing value on reload.
8. The primary paired contrast family contains recall and workload tests for adjacent component contrasts and full-versus-baseline, fixed by the caller before analysis. Absent operating points/units must not be replaced by diagnostics for a feasible-operation claim. No aggregate real-data inferential result is produced in this bounded task.
