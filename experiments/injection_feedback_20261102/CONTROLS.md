# Controls added after the BDG2 paired result

Chosen after observing the BDG2 history dependence for stuck readings. This is a targeted follow-up, independent of the original design decision. Freeze before examining control outcomes.

- BDG2. Compare the primary live CQR treatment with a simple run-length alarm for repeated meter values. Select a global minimum number of consecutive unchanged transitions in 1 through 96 using original selection-period readings only. Target up to 0.5 episodes per meter-day and at most 20% of hours in alarm using the same episode definition. Compare each detector's achieved background workload and first alarms while changes are present. A stand-alone flatline rule is a specialist comparator.
- PLEIAData. Use the existing attributed ten-minute temperature truth export at the repository baseline. Deduplicate two nominal coverages, verify one value per target and enforce ten-minute continuity. Use the first 50%, next 15%, next 15% and final 20% of calendar time as fit, calibration, selection and test. Fit a different regression backbone (ridge autoregression with calendar terms and lagged temperatures), symmetric calibrated absolute-error bands, and a four-sample-delayed version. Add the same standalone flatline rule. Target a maximum 0.5 background episodes per day in selection with a 20% active-time cap. Keep weights, selection and background identical between clean-history and feedback replays for the same model.
- Five deterministic schedules with equal rotating durations of two, four and eight samples. Inject a stuck sensor by repeating the last observed value for the whole slot. Count only effective events and require contiguous support over the complete matching window. The primary external outcome is first-onset detection inside the interval between first and last changed readings, reported by duration and pooled. Also compare hit rates including three grace samples. Report denominators, any small-sample issues and achieved workloads. This independent stream has synthetic faults and is exploratory. It supports a cross-domain direction check, not a population conclusion. Neither archived model predictions nor fault labels are used to train the external forecasters.
